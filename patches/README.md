# Dependency patches

## Radix DismissableLayer: Escape on a fresh layer

`@radix-ui/react-dismissable-layer@1.1.11` decides whether a layer is the top
one from an `index` computed during render. A layer registers itself in a
passive effect and learns its real index only from the re-render that
registration triggers, which React schedules at default priority. Browsers
deliver input ahead of that render, so an Escape pressed just after a dialog
opens and takes focus reaches no layer: the keydown goes unhandled and the
dialog stays open. A heavy dialog (the task trigger dialog) widens the window
to tens of milliseconds. The patch reads the live layer stack when the key
arrives. Upstream 1.2.x still uses the render-time index; drop the patch once a
release checks the stack at event time.

# ACP adapter patches

## Package-manager compatibility

Both ACP adapter patches (`claude-agent-acp@0.100.0`, `codex-acp@2.5.0`) are
declared in both package.json (pnpm 9 / CI) and pnpm-workspace.yaml (newer
pnpm), matching this repository's package-manager compatibility convention.

The committed patch hash is generated by CI's pnpm 9. Use
`corepack pnpm install --frozen-lockfile` for a reproducible install: package.json
pins pnpm 9.15.9. The source-build helper selects the same version through
Corepack, or checks that PATH pnpm exactly matches when Corepack is unavailable.
pnpm 11 uses a different patch hash and rejects this lockfile with
`ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` in frozen mode; a non-frozen install rewrites
the hash. Keep lockfile changes in pnpm 9's format until the repository migrates
its package-manager version or these patches are removed. Regenerate a patch with
`corepack pnpm patch <pkg>@<ver>` and `corepack pnpm patch-commit <dir>`, then
mirror the entry into pnpm-workspace.yaml.

The Codex idle steering fallback (`_meta.steering.idleBehavior: "promptRequired"`
→ `{ outcome: "promptRequired", reason: "noRunningTurn" }`) is no longer patched:
upstream merged it in codex-acp 2.4.0 (agentclientprotocol/codex-acp#593) with
the response shape the driver already expects.

## Claude steering priority and withdrawal

Claude Code delivers a steer at priority `now` by default, which aborts the
running cycle. The patch uses `next`, so a steer folds in after the current tool
batch without aborting a running tool, and the reply arrives as a split response.
`later` is kept while a permission/elicitation callback is open (IJAI-1191).

Because a `next` steer can sit queued in Claude Code, Stop withdraws queued steers
(`cancelAsyncMessage`) before interrupting, under one shared time budget, and
reconciles orphan accounting by UUID (`pendingOrphanResultUuids`) so a withdrawn
or dropped steer is counted once. Withdrawal never interrupts a replacement turn.
Since 0.100.0 a prompt received after the cancel stays queued behind the target
(upstream `cancelledThrough`) and survives the interrupt; it counts as a
replacement only once the target has left `activeTurn`.

## Runtime receipt confirmations

Both bundled adapters expose a private `dispatch/steering` extension in ACP
`_meta`. Initialization advertises `{ pickupReceipts: true, promptReceipts: true }`; a prompt or steering request
carries `{ id: <UUID> }`; a `session_info_update` carries `{ pickedUp: <UUID> }`.
The UUID identifies the delivery attempt, independently of message text. This is
an observation from the runtime, not a claim that the model understood or obeyed
the message.

- Codex forwards the ID as `turn/start.clientUserMessageId` or `turn/steer.clientUserMessageId` and reports it only
  when a live `item/started` user-message item returns that `clientId`. Since
  2.5.0 upstream mints its own `clientUserMessageId` for steers (and matches the
  landing with `isInsertedUserMessage`); the patch substitutes the Dispatch
  receipt UUID there and on the prompt's `turn/start`, so upstream's own landing
  tracking and Dispatch's receipt share one id. This occurs
  when pending input enters the turn, potentially after an outstanding tool call.
- Claude assigns the UUID to the streamed user message and reports pickup when
  the SDK echoes that UUID from a queued prompt or the current turn's `steeredEchoes` set. For normal prompts, a CLI `command_lifecycle.started` frame naming the same UUID also confirms pickup, covering missing echoes. Queued/terminal frames and unrelated IDs never produce receipts.

Dispatch correlates session and attempt, buffers a receipt that races the steer
acknowledgement, journals acceptance before pickup, and persists receipts per
post/recipient. Retry clears only the retried recipients' receipts. Turn completion
alone never marks pickup. Adapters without this capability retain delivery-only behavior; an older Codex CLI that does not return
`clientId` stays at Sent. Raw ACP commands skip prompt receipts
because some commands do not emit a user-message echo.

A noninteractive mark in a reserved message margin shows Sent until pickup,
briefly confirms Received, then fades away. It sits outside the action toolbar;
status changes never resize the message or move with the buttons. There is no
delivery popover. Completed history is quiet on initial load. For multiple
recipients, Received waits for every receipt; partial pickup stays Sent.
True queues and delivery failures retain their callouts/actions.
The persisted JSONB column and private wire namespace retain their historical
steering names for compatibility; they now carry normal-prompt receipts too.

Validated against real authenticated Codex and Claude processes. In the Codex
probe, steer acceptance preceded pickup by about eight seconds while a shell tool
ran; Claude's matching echo followed acceptance before the steered response
completed. Driver and database tests cover races, session correlation, repeated
text, replay, recipient isolation, and retry invalidation.

Remove these receipt hunks when upstream provides equivalent correlated runtime
pickup notifications, and translate those notifications at the driver boundary.

## Codex turn boundaries

Codex can start turns of its own between prompts (a goal continuation), and
codex-acp maps app-server `turn/started` / `turn/completed` to no ACP update,
so a client cannot tell where such a turn begins or ends. The patch forwards
both as a `session_info_update` carrying
`_meta["dispatch/turn"] = { state: "started" | "completed", turnId, status?, error? }`.
A prompt's response also carries `_meta["dispatch/turn"] = { turnId }`, the
turn it ran as, so ownership never depends on marker order (a goal
continuation can start just before the prompt's own turn). Once the prompt
settles, the driver opens a self-started turn for any other turn that started
during it and is still running; while idle, a `started` opens one, and the
matching `completed` settles it. Since 2.5.0 a prompt's `turn/start` can adopt
a turn Codex already runs; the response then names that turn, which the driver
treats as the prompt's own (it waits out an open self-started turn before
prompting, so this only happens in a start race). The patch passes the turn id
through both `onTurnStarted` call sites, which upstream calls without one.

Claude needs no patch here: Dispatch never advertises the AIR async-tasks
client capability (`clientSupportsAsyncTasks`; its session capabilities are only
`notices` and `compaction`), so claude-agent-acp 0.100.0 still streams an autonomous cycle as plain updates and
tags its final `usage_update` with `_meta["_claude/origin"]`; the async-task
publication added in 0.95 (#1390) stays off.

## Read-only MCP inventory (v1)

Both pinned adapters advertise `_meta["dispatch/mcpInventory"] = { version: 1 }`
from initialize and accept `_dispatch/mcpInventory` with the live `sessionId`.
Claude reads the existing query's `mcpServerStatus()`; Codex reads every page of
`mcpServerStatus/list` with `threadId` and `detail: "toolsAndAuthOnly"`. Neither
extension opens a turn, reconnects a server, reloads configuration, or signs in.
They return only `{ version: 1, servers: [{ name, state, toolsState, tools }] }`;
tools contain names and optional descriptions. Unknown/unavailable discovery is
`tools: null`, distinct from a known empty array. Native errors, configuration,
URLs, headers, tool schemas and authentication metadata are excluded.

Missing sessions are rejected. Closed/replaced Claude queries and changed Codex
session generations invalidate in-flight reads. Dispatch additionally gates old
hosts/adapters, bounds request time, validates/projects the response and discards
results when the owning process changes. Installed-adapter tests exercise this
contract alongside the existing cancellation and steering regressions.
