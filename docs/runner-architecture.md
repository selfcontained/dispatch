# How Dispatch runs work on an agent’s machine

Dispatch records which runner owns a session. To inspect its checkout, for example, the controller selects the runner by the session’s stored placement and calls `checkout.read` with a session handle and a checkout selector. The runner resolves the path under the workload account. A path reported by an enrolled runner can be displayed on the controller without being opened there.

## Packages and connections

| Component                     | Responsibility                                                                                                                                                                                                |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/runner-protocol`    | Defines the portable Runner contract, request and response schemas, typed errors, channels, and retry semantics. Start with [the operation registry](../packages/runner-protocol/src/contract/operations.ts). |
| `packages/runner-client`      | Opens connections, frames calls and replies, applies stream backpressure, and attaches to session hosts. The local launcher starts the child process.                                                         |
| `packages/runner`             | The standalone runner program and workload implementations. It owns engine processes, terminal sessions, filesystem operations, and Git commands on the session machine.                                      |
| `packages/runner-conformance` | Exercises the same contract against runner implementations.                                                                                                                                                   |
| `apps/server/src/runners`     | Selects the adapter and supplies Dispatch-owned settings and policy. Dispatch owns admission, persistent agent and project records, archive decisions, and update coordination.                               |

The local adapter normally calls the child over an authenticated socket. The server entry also supplies the same workload implementation in process for local recovery. A read already sent to a connected child waits for its reply, cancellation, or connection loss. The adapter can repeat eligible reads after a lost connection, even though a disconnect alone does not prove the child exited. A live but hung child can stall reads. The supervisor logs unanswered health checks and leaves the child running.

An enrolled runner connects outbound over authenticated TLS. Dispatch selects the connection using its registration and checks session ownership before sending. The runner resolves the handle against its bindings. A lost enrolled read returns `unavailable`. A lost mutation acknowledgement returns `unknown_outcome` because automatic replay could execute the command twice. See the [Linux installation guide](remote-runner-linux.md).

## Keeping the boundary intact

Run `node scripts/check-runner-boundary.mjs --strict` to check placement reads, controller access to workload resources, local side channels, package imports, web dependencies on runner internals, and known restrictions. Use `--print` to locate a violation. The baseline and move ledger must remain empty. CI checks the source and baseline history. Behavioral coverage comes from [the conformance package](../packages/runner-conformance) and the local parity oracle, which compares the head with [pinned main](../scripts/runner-local-parity/main-pin.json).

An exception identifies the owning file, capability, import, or compatibility token and the reason it belongs there. Examples include reading controller-held attachments for delivery, composing workload ports at the server entry, retaining a persisted host field, and using an engine scope key in runner management. Add a regression case proving the capability still counts elsewhere. Keep deferred exceptions attached to their owner decision. See [the scanner](../scripts/check-runner-boundary.mjs) and [restriction anchors](../scripts/runner-restrictions.mjs).

## Known differences from main and deferred gaps

- **Archive and hooks.** On every runner, unreadable or timed-out Git status during automatic archive keeps the checkout and branch, clears remembered removal authorization, and reports the cleanup failure. Force skips that status read. Enrolled sessions run repository archive hooks too. A disconnected runner can leave an archive pending. An uncertain hook outcome retains the agent for reconciliation. Legacy hosts without ownership proof are never swept.
- **FIFO hook manifests.** Main caches parsed hooks by path and modification time. If preview consumes a FIFO’s only writer, main can reuse the cached command during archive. The runner rereads the manifest and waits for another writer. The owner accepted this difference.
- **Placement and discovery.** Agent records expose placement and worktree ownership. Jobs and templates can select a runner. A project can keep several folders for one repository. Model discovery serves the cached catalog during refresh and validation waits for its first observation. Expected API and persistence differences are recorded in [the parity ledger](../scripts/runner-local-parity/intended-differences.json).
- **Ports, previews and screencasts (T39).** Port forwarding, port-backed previews, and Playwright screencasts on enrolled runners are deferred. CDP discovery uses controller loopback, and starting an enrolled screencast returns HTTP 409. Open in IDE isn't shown for runner agents, whose checkout is on another machine. A runner agent’s login link also requires a reachable Dispatch listener.
- **Launch and transport limits.** Enrolled launches accept one MCP server, with HTTPS, a scoped token and the enrollment CA. Enrolled command-manifest discovery has a 256 KiB ceiling. Local discovery reads the full file. Enrolled checkout views have a 16 MiB reply budget plus metadata, and native definition reads retain a 300-second transport deadline. Project targets offer repository selection and currently have empty folder history. The starting-branch picker lists returned branches. The launch API also accepts a PR URL or an explicitly supplied branch that the picker does not offer.
- **Session personas and ownership.** Session listings omit directories, dangling links and FIFOs named `*.md`. Native persona loading warns on directories or dangling links and can wait on a FIFO. Session persona routes that read an ownership map can give a different availability result from a native existence check. The assessor uses native presence and read operations on the owned checkout. A persona upsert retries an explicitly stale digest up to three attempts.
- **GitHub credentials.** Signing in configures the workload account’s Git credential helper for HTTPS on github.com. Revoking a runner leaves that machine’s GitHub CLI session signed in. SSH remotes and other hosts use their own configuration.
